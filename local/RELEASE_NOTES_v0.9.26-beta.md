# v0.9.26-beta

## 🔴 비상 청산("전량 매도 후 매수 중지") 구조적 재설계 — 더 이상 멈추지 않음

웹에서 **"전량 매도 후 매수 중지"(LIQUIDATE_ALL)**를 눌렀을 때 kill-switch는 발동하나
**dataset 다운로드 단계에서 멈춰 실제 청산이 안 되던** 구조적 결함을 근본 해결했습니다.

### 무엇이 문제였나
비상 청산이 일반 매매 사이클(run_cycle)을 그대로 재사용해, 사이클의 무거운 의존성을
모두 상속받았습니다 — 시세 dataset **다운로드를 선행 필수**로 두는데, 서버/네트워크가
불안정하면 이 다운로드가 최대 5분 멈춰(hang) **비상정지 전체가 막히고 주문이 0건**이
됐습니다. 청산 대상도 전략·원장에 묶여 **전략이 삭제된 보유분(고아)·외부 보유분**이
누락되고, 한 번에 한 시장만 처리됐습니다.

### 어떻게 고쳤나
**비상정지는 안전 기능이므로 최소 의존·격리되어야 한다**는 원칙으로 일반 사이클에서
완전히 분리했습니다.
- 청산 대상을 **계좌 실보유에서 직접** 취득 — 전략·원장·dataset과 무관하게 보유분 전량
  청산(고아·외부 보유분 포함). **국내·미국·선물 보유 전체를 한 번에**.
- **dataset 다운로드·신호 평가에 의존하지 않음** — 보유분 매도엔 불필요. 시세는 KIS
  현재가, 못 구하면 시장가 주문. 열린 시장은 즉시 체결, 닫힌 시장은 "장마감 거부"로
  명확히 표시.

## ⚙️ 정규 사이클 안정성 — dataset 다운로드 fast-fail

정규 자동매매 사이클의 dataset 다운로드 timeout을 단일 5분에서 **(연결 10초 / 무수신
30초)**로 바꿔, 서버·네트워크가 멈춰도 **수십 초 내 기존 캐시로 폴백**하도록 했습니다.
이전엔 다운로드 stall 시 사이클이 최대 5분 멈출 수 있었습니다.

---
검증: 신규 단위 테스트 7(비상 청산 격리 5 + dataset fast-fail 2) + 로컬 전체 회귀 green.
주식 자동매매 사이클 동작은 무변경(byte-identical).
