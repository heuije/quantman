## 3. 단계별 테스트

### C-0 · 연결 + 필드 실측 (읽기 전용 · 언제나 안전)

```powershell
python verify_ls.py            # 토큰 → 잔고(t0424) → 시세(t1102) → 미체결(t0425) raw 덤프
python verify_ls.py --kosdaq   # + KOSDAQ(035720) 시세 — exchgubun 확정
```

- 주문을 내지 않으므로 **장 시간 무관·무위험**. 토큰/잔고/시세만 조회.
- 출력의 모든 `===== RAW: ... =====` 블록을 **통째로 복사해 전달**한다(자격증명·계좌번호는 자동 마스킹됨).
- **여기서 §4 체크리스트의 G15·G16·G20·G21 + 미확인 일부가 한 번에 확정된다.**
- 합격 기준: 토큰 OK · 잔고 파싱값이 0/`fetch_failed` 아님 · 시세>0. 0 이면 RAW 에서 실제 필드명 확인 → 교정.

### C-1 · 주문 라운드트립 + 체결 인지 (모의 · **장중 09:00~15:20**)

```powershell
python verify_ls.py --order    # 1주 시장가 매수 → 체결조회 폴링 → t0425 chegb=0 → 정리(매도/취소)
```

- **모의 자금 · 1주.** 장중에만 체결된다(장외면 미체결 → 자동 취소).
- 캡처 포인트:
  - **[5a]** CSPAT00601 매수 응답 raw → **성공 rsp_cd(00040?) · OrdNo 블록/필드명** 확정(G17·G11).
  - **[5b]** `order_status` 폴링 → 현 `chegb=2` 로 체결을 인지하는지/사라지는지 관찰(G10).
  - **[5c] ★당일매매 핵심★** t0425 `chegb=0` raw → **체결/취소를 구분하는 `status` 필드·값** 확정(G19).
  - **[5d]** 보유분 매도 또는 미체결 취소 → 매도/취소 응답 raw.
- 합격 기준: 매수 `success=True` · OrdNo 존재 · `chegb=0` 응답에서 체결행의 status 값 식별 가능.

### C-2 · 풀 사이클 E2E (모의 · 통합 흐름)

C-1 의 필드 교정을 반영한 뒤, **로컬앱 자동매매 사이클**로 통합 검증:

```powershell
# 웹에서 LS 모의에 배정된 간단 전략 1개(예: 1종목 시가매수·종가청산, hold_days=0) 준비 후
python run.py cycle     # 자동매매 사이클 1회 — fill→ledger→포지션 관리→(종가)청산
```

- **검증 대상(단위테스트가 못 잡는 통합 결함)**:
  - 체결이 **ledger 에 반영**되는가(trader.py 의 fill-gated ledger).
  - **hold_days=0 당일매매**의 종가청산이 동작하는가(체결 인지가 안 되면 여기서 실패 — G19 가 막던 지점).
  - 정산 reconcile 이 보유분을 `external_extras`(미관리)로 잘못 분류하지 않는가.
- 합격 기준: 매수→체결→ledger 기록→종가청산까지 1회 완주. SimBroker 골든 회귀 byte-identical 유지.

### C-3 · 실전 마이크로 게이트 (모든 모의 통과 후에만)

- 실전 키로 전환(GUI 에서 "모의투자" 해제·실전 키 저장) → **1주 마이크로 실거래 1건** → 정상 체결·청산 확인 → 점진 개방.
- `verify_ls.py --order` 는 실전 키 감지 시 `'REAL'` 명시 입력을 요구한다(오발주 방지).

> **rate-limit 인코딩(중요)**: LS 가 rate-limit 을 `HTTP 200 + body(rsp_cd≠성공)` 로 주는지, `HTTP 429/5xx` 로 주는지 실측.
> 현 `_post` 는 429/5xx 만 재시도한다. 200+에러body 면 재시도가 누락된다(오체결은 없음 — normalize 가 거부판정). E2 와 함께 확정.
