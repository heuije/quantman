# 재무제표 원문(전자공시 보고서) 파싱 — 다세션 작업 계획·핸드오프

〔담당: 희제〕 개별종목분석 Financials 탭. **목표: PL·BS·CF의 표시순서·계정명·값을 DART
보고서(viewer)와 100% 동일하게.** 연간+분기 전부. (사용자 결정: 표준순서 근사 아님, 원문 파싱.)

## 왜 원문 파싱인가 (배경)
- DART **OpenAPI `fnlttSinglAcntAll`** 은 손익(IS/CIS)을 **XBRL 요소순**으로 준다 → 매출액이 맨 뒤,
  영업이익이 맨 위 등 표시순서가 깨짐. `ord`·응답 list 순서 둘 다 요소순(표시순서 아님). BS는 마침 ord가
  표시순서와 일치, CF는 활동별 그룹은 되나 순서 비관습적.
- 보고서 **viewer(dart.fss.or.kr/dsaf001)** 은 정확한 표시순서지만, 그 순서를 **OpenAPI가 안 줌.**
- 따라서 보고서와 동일하려면 **원문 문서(`document.xml` ZIP의 HTML 표)** 를 파싱해야 함.

## 현재 진행분 (server/app/dart_doc.py) — 작동 확인
- `document.xml?rcept_no=` → ZIP(메인 6.4MB + 첨부 xml). 첨부/메인의 `<TABLE>` HTML 파싱(BeautifulSoup).
- **PL·CF: 삼성SDI(rcpNo 20260310002954) 보고서와 순서·계정명·값·연도 정확 일치 검증 완료.**
  - 예: PL = 매출액(13.27조)→매출원가→매출총이익→기타영업수익→판관비→영업손익→기타수익→… (보고서 그대로)
- 연결/별도 구분: **OpenAPI 연결값(latest년 매출액·자산총계·영업CF)과 표 시그니처 행 값을 대조**해
  일치 표를 연결로 확정(refs). 가장 신뢰 가능한 방법.
- 연도매핑: `_year_map` — '제 56기 … 2025년 12월 31일 (까지/현재)' 앵커로 base=연도−기수.
- 값: 원 → 억원(/1e8). 음수는 (괄호). 계정 접두번호(I./1./(1)/①) 제거.

## 함정 (재발견 방지 — 반드시 숙지)
1. **날짜 형식**: 원문은 `2025년 01월 01일`(년월일), viewer는 `2025.01.01`(점). 정규식 둘 다 허용해야 함.
   (이거 못 잡아 한참 헤맴.)
2. **연결 BS 위치**: 삼성SDI는 연결 BS(자산총계)가 **첨부가 아니라 6.4MB 메인 문서(표 2,305개)** 안에 있음.
   회사마다 첨부/메인 위치가 다름 → 전 파일 스캔 + refs로 연결표 확정 필요.
3. **기간 열 수**: 표마다 2개년/3개년 혼재. 5개년 = 최신 사업보고서(3년) + 2년전 사업보고서(3년) 병합.
4. **연결/별도 둘 다 존재**: 메인엔 요약재무정보·연결·별도가 다 있음 → refs(연결값) 매칭 필수(첫 표 X).

## 추가 발견 (2026-06-25 진행분)
- **BS 정상화**: 총계 계정이 회사마다 `자산총계`/`자산 합계` 등 → 시그니처·ref 둘 다 넓힘(`_SIG['BS']`,
  `_has_sig`). 삼성SDI BS도 보고서 순서대로 파싱 확인(유동자산→현금→매출채권→재고…).
- **전체 statement는 2개년(당기·전기)만**: IFRS 연결 포괄손익/재무상태표는 비교기간 1기만 → 전 계정 표는
  당기+전기 2개년. 3개년(제54기 등)은 **요약재무정보(condensed)** 에만 있음(전 계정 아님).
  → **5개년 = 사업보고서 3건(예: 2025·2023·2021) 파싱 후 병합**이 정답(2건으론 4개년만).
- **표 선택**: 후보 표 중 `기간열 최다` 채택(요약 2개년 vs 전체 2개년 — 행수 많은 전체를 추가 우선 필요할 수
  있음. 현재는 기간 동률이면 먼저 매칭된 것). refs(연결값 대조)로 연결/별도/요약 구분.

## ✅ 채택 아키텍처 (2026-06-25 완성) — "원문 순서 + OpenAPI 값" 하이브리드
무거운 5개년 문서병합(restatement·FY-4 파싱난) 대신 **가벼운 순서전용 파싱**으로 전환:
- **`fetch_order(code)`** = 최신 사업보고서 1건만 파싱 → `{sj: [(ckey, sign)...]}`. 즉 **계정 표시순서 +
  계정별 표기부호**만 추출(값은 안 씀). 문서 1개만 받으면 됨(경량).
- **값·기간**은 OpenAPI(`dart.fetch`, 연간 5개년 + 분기 단일분기)에서 — restatement 반영된 최신 일관값.
- **`financials._reorder_by_doc(stmt, layout)`**: OpenAPI rows를 보고서 순서로 제자리 재배치
  (`_ckey`로 영업손익↔영업이익 흡수) + **같은계정명 중복(유동/비유동 매출채권)은 등장순 1:1 배정** +
  **부호 정합**(보고서 부호와 OpenAPI 부호가 '다를 때만' 반전 → 비용 음수표기 회사 반영, 단 영업이익(손실)
  처럼 연도별 흑/적 바뀌는 계정은 OpenAPI 실제값 보존).
- `financials._fetch`: `draw=dart.fetch` 후 `order=dart_doc.fetch_order` → 연간·분기 PL/BS/CF 각각
  `_reorder_by_doc` → `_with_change`/`_add_pl_metrics`/`_graft_sga`. fetch_order 실패 시 OpenAPI 순서 폴백
  (무회귀).

### parse_doc 견고화 (회사별 포맷 차이 흡수) — 이걸로 대형주까지 커버
1. **단위 자동보정**: 회사마다 원/천원/백만원 다름 → 시그행 raw값이 ref(억원)와 맞는 나눗수
   (원1e8·천원1e5·백만원1e2) 자동탐색. **삼성SDI=원, 삼성전자=백만원**. (이거 못 잡아 삼성전자 계속 실패했음.)
2. **헤더 `제57기`(당/전 표기 없음)** 허용 — `제\d+\s*(?:기|\(?[당전])`.
3. **음수 △▲- 인식**(`_num`) — 삼성전자 등은 괄호 아닌 △ 사용.
4. **주석참조 `(주4,29)` 제거**(`_clean`) — 안 지우면 OpenAPI 계정명과 _ckey 불일치.
5. **요약재무정보 제외**: 요약표는 PL·BS·CF sig 3개 동시 → 단일 sig 표만 채택(`len(present)==1`).
6. **표 선택 = 행수 최다**(요약 아닌 전체 statement). 헤더행 `구분/항목/계정` 누출 필터.

### 검증 (10개 다양 회사 OK)
- 삼성전자/삼성SDI/에코프로비엠/현대차/SK하이닉스/셀트리온/현대모비스/현대차: PL·BS·CF 보고서 순서·부호·값 정확.
- NAVER/카카오: 영업수익·영업비용 포맷(filed) 정상. LG화학: 영업수익 시작(filed).
- **한계 — 은행·금융지주**(KB금융 등): PL이 이자수익 기반이라 매출액 sig 없음 → **PL만 OpenAPI 폴백**
  (BS·CF는 정상). 소수라 후속 보완(=`_SIG['PL']`에 이자수익류 추가 + 은행 refs). 무회귀.
- to_xlsx SUBTOTAL: BS=`=SUBTOTAL`(양수), 손익 판관비=`=-SUBTOTAL`(음수표기 회사 자동판정), CF는
  중첩소계(영업에서창출된현금⊃당기순익+조정+변동) 이중계상이라 **제외**(활동소계는 보고서 원본값).
