## 다중 세션 브리핑 프로토콜 (이 PC 전용 · 세션 align)

다른 세션이 내 작업을 정확히 이어받고 충돌을 피하도록, 작업 생애 두 시점에 공유 로그에 기록한다.

**`--intent` 는 self-contained 핸드오프로 2~3문장.** 다른 세션이 *사전 맥락 없이* 읽고
이해하도록: 무엇을·왜 + 배경(어느 시스템/계층인지, 어떤 문제 때문인지, 어디로 향하는지) +
범위 경계(무엇은 안 하는지). 한 단어·한 구절은 금지. 나머지 필드는 한 줄로 충분.

### ① 작업 시작 시 — 의도(2~3문장)·계획·파일 명시
새 작업(유저의 새 요청)에 착수하면 한 번:
```
python ~/.claude/hooks/brief.py start \
  --intent "<2~3문장 self-contained: 무엇을·왜·배경·범위경계>" \
  --plan   "어떻게 - 핵심 단계" \
  --files  "건드릴 파일/영역"
```
예) --intent "라이브 체결기를 롱 전용→양방향(롱/숏)으로 확장한다. trader가 매수만 발주하고
ledger가 qty>=0이라 숏을 못 다루는 게 문제. 단일·선물 directional(score 부호=방향)을 on_signal
라이브 경로로 실행하는 게 목표이며, 랭킹형 long_short(횡단)는 v1 범위 밖이라 차단 유지."

### ② 작업 완료 시 — 어떻게 끝났는지 명시
작업을 마치면(머지·커밋·보류·중단 모두 포함) 한 번:
```
python ~/.claude/hooks/brief.py done \
  --intent  "<2~3문장 self-contained 재확인: 무엇을·왜·배경>" \
  --plan    "실제로 한 것" \
  --files   "최종 변경 파일" \
  --impl    "구현/결정 요지 - 다른 세션이 알아야 할 핵심" \
  --outcome "어떻게 끝났나 - 머지/PR번호/배포/보류/중단/미배선 등"
```

### 규칙
- 매 프롬프트 시작 시 "다른 세션 작업 현황"이 자동 주입된다(안 본 것만 catch-up). 내 작업과 겹치면 시작 전 반드시 고려.
- 상태 공유만 — 다른 세션에 작업을 시키거나 명령하지 않는다.
- 짧게. 사소한 작업까지 기록하지 않는다(공동개발자 행동이 달라질 정보만 — 4원칙).
- 다른 개발자가 알아야 할 내용은 여기 더해 draft PR 본문 / 프로젝트 CLAUDE.md §2 에도 남긴다.
