## 0. 진단 요약 — 갭은 20개가 아니라 5개다

가설 프로브 30선(코드 정독 판정 ✅15/🟡8/❌7)과 프로덕션 이용 로그 전수(121턴)에서 확정된
미지원 갭(G1~G12)·품질 마찰은 **독립 결함이 아니라 IR 대수에 빠진 차원 4개 + 발견성 1개**로 수렴한다:

| 뿌리 | 빠진 것 | 증상(실수요 근거) |
|---|---|---|
| R1 이벤트 시간방향 | `Study.windows`가 forward-only | 전조 분석 불가 — prod 3대화(#50 "급등 전 조짐"·#22·#27) |
| R2 축 조합성 | `study.axis` 단일 enum | 이벤트×파라미터 격자 거부(#22·#27)·신호 대안 N개 비교 불가(#33) |
| R3 전략 합성 | StrategyIR을 합칠 수 없음(모노이드 아님) | "이와 별개로 병행"(#25·#28)·기본 페어 |
| R4 자본 흐름 | `initial_capital` 고정(닫힌 계) | 적립식 DCA 불가(#23 "매달 100만원씩"→0거래) |
| R5 발견성 | 존재하는 데이터를 찾을 수 없음 | `원달러환율`(DEXKOUS) 있는데 챗이 포기(#42)·노바렉스 오코드 연쇄(#40·#12) |

+ **데이터 트랙**(설계가 아니라 수집·배선이 필요한 것)과 **완결 소형 3건**(G3 증거금 오버라이드·
달력 신호게이트 관용구·exit.fill 노출).

## 1. 설계 원칙

1. **차원을 채운다, 옵션을 붙이지 않는다.** 각 WS는 기존 atom(windows·param_grid·StrategyIR·
   SimSpec·심볼계층)의 대수적 완성이다. 신규 전용 필드는 기존 atom 조합으로 불가능할 때만.
2. **능력계약(PR#359) 위에 선언한다.** WS1~4의 새 능력은 RunnerContract 레지스트리에 등록해
   광고·검증·자기서술이 파생되게 한다. 359 이전 랜딩 금지(손동기화 표면 재생산 금지).
3. **수용 기준 = 실패한 프로덕션 쿼리 리플레이.** 각 WS는 실제 실패 대화의 쿼리를 $0 하니스로
   재실행해 성공(또는 정직한 계약 응답)을 증명해야 완료다. + 골든 411 보존(기존 IR byte-identical).
4. **정직한 비목표를 문서화한다.** 분봉 인트라데이(데이터 부재)·옵션(보류 결정)·PIT 추정치 소급
   (물리 불가·전진 축적은 기존 원칙)·FX 환산(수요 0)·조인트 마진 멀티레그(§WS3 비목표) 는
   이번 캠페인이 다루지 않으며, capabilities에 한계로 명시한다.

## 2. 워크스트림

### WS5 — 발견성 (즉시 착수 · 엔진 무접촉) ✅ 이 PR

**문제 부류:** 챗이 존재하는 데이터·종목을 못 찾는다. ①매크로 심볼(한글명) 인벤토리가 모델에
미노출 → `USDKRW`·`KRW=X` 추측 후 "조회 불가" 포기(#42, 실제로는 `원달러환율` 존재).
②종목명→코드 해석이 별칭 테이블 정확일치뿐 → 중소형주(노바렉스)에서 오코드 연쇄(#40·#12),
describe가 '다른 회사'를 반환해도 사후 감지.

**해결(단일 choke):**
- `quant_core.ticker_db.search_symbols(query)` — 주식(ticker_db 9,397종) + 매크로/선물/지수
  (data_fetcher 심볼 계층)를 한 함수로 fuzzy 검색(정확>접두>포함, 시장·유형 태깅).
- 챗 도구 `resolve_symbol` 신설(엔진 우회 계열, inspect와 동급) — 이름이 불확실할 때 후보
  목록(이름·코드·유형·거래소)을 1콜로.
- **미스 주도 발견(error-driven discovery):** `inspect`/`describe` 심볼 미해결 시 실패 메시지에
  유사 후보 자동 제안(같은 search 함수 재사용). 프롬프트 비대화 없이 실패가 스스로 길을 안내.
- 프롬프트 `<macro_symbols>` 섹션: 매크로 심볼 한글명을 그룹별 1줄로 노출(금리·환율/원자재/
  지수선물/COT/국채…). 이미 있는 `<data_inventory>`와 달리 *심볼 이름 자체*를 알려준다.

**수용:** conv #42 리플레이("원/달러 환율 추이 분석") → 원달러환율 시계열 조회 성공.
노바렉스·코스맥스엔비티 이름 검색 → 정코드 후보 반환.

### F9-웹 — exit.fill 빌더 노출 (즉시 착수 · 별도 브랜치)

v0.9.71 릴리스로 D5 게이트 해제. 웹 전략빌더(StrategyDetail)에 청산 체결 시점(next_open|close)

### WS1 — 이벤트 시간방향 (PR#359 랜딩 후)

`Study.windows`에 부호 있는 정수 허용(`[-240,-120,0,20]`). `_event_paths`를 event-anchored
양방향 경로 수집으로 일반화 — 음수 인덱스 wrap 금지(359 P0 가드를 '지원'으로 승격), pre-창이
부족한 조기 이벤트는 탈락 회계(359 P3 회계와 정합). 전/후 구간 요약·contrast(전반 vs 후반) +
이벤트 날짜 원자료 표준 노출(엑셀 이벤트원자료와 동일 계약). 자기서술("이벤트 전 N일")·웹
EventStudyChart 음수축 렌더 포함.
**수용:** conv #50 리플레이(급등 전 12개월 전반/후반 대조) · #36(날짜 목록).

### WS2 — 축 조합성 (PR#359 랜딩 후)

- **W2a `param_grid × relate(event)`:** 2-D 금지 가드를 "모호한 조합만 거부"로 정밀화 —
  이벤트 정의 내부 경로의 격자 재실행(버킷=격자점, 각 버킷=이벤트스터디 요약). extremize
  objective에 이벤트 지표(mean_fwd_w·t_stat·pre_drift) 추가.
- **W2b `axis=variant`:** 이름 붙은 신호 트리 대안 목록(`variants: [{name, signal}]`)을
  버킷으로 비교 — assets(심볼 목록)·param_grid(스칼라 목록)의 자연 완성인 '구조 목록' 축.
**수용:** conv #22/#27 리플레이(VIX 임계값×윈도우 탐색) · #33(조건 A/B/C/D 1콜).

### WS3 — 전략 합성 · 수익률 수준 (PR#359 랜딩 후)

`StrategyIR.components: [{ir, weight}]` (top-level signal/position과 상호배타). 각 컴포넌트를
기존 엔진으로 독립 실행 → 일일 수익률 가중 합산(+구성 리밸런스 정책) → 합성 equity + 컴포넌트
분해 버킷. 라이브 게이트: components 전략은 자동매매 승격 차단(백테스트 전용 — 정직).
**비목표(명시):** 공동 증거금·동시 체결 회계의 조인트 멀티레그. capabilities에 한계 문구.
**수용:** conv #25/#28 리플레이("병행" 합산 전략) · 기본 페어(같은 신호 A롱+B숏 2컴포넌트).

### WS4 — 자본 흐름 (PR#359 랜딩 후)

`SimSpec.contributions: {schedule: monthly|…, amount}` — 엔진 NAV 회계에 외부 현금 유입 +
지표를 TWR(시간가중, 기존 지표 유지)/원금 대비(납입 누계 vs 평가액) 분리 보고. 웹·엑셀에
납입 누계 라인 추가.
**수용:** conv #23 리플레이("매달 100만원씩") — 0거래가 아닌 적립 매수 시뮬레이션.

### 소형 — G3·달력 관용구 (WS1~4 페이즈에 동승)

- **G3:** `simulation.margin_pct_override` — 선물 증거금률 what-if(백테스트 전용, leverage>1과
  같은 계열로 모의/실전 차단 + 방법론에 '실제 거래소 증거금과 다름' 명시). 수용: conv #47/#25.
- **달력 신호게이트 관용구:** capabilities에 `is_in(calendar('month'),[…])` 신호 사용 예시
  (Part 1 L2-a). 359의 capabilities 파생 구조 위에서.

## 4. 순서와 충돌 관리


## 5. 리스크·한계 (정직)

- WS3 수익률 합성은 증거금 효율·다리 간 드리프트를 모델하지 않는다(방법론에 명시). 진짜
  멀티레그 수요가 실측되면 별도 캠페인.
- WS2 격자×이벤트는 다중비교 함정(스누핑)을 키운다 — extremize의 OOS 가드·시행 수 표기(359
  능력계약의 정직 서술)와 반드시 동승.
- WS4는 지표 이중화(TWR/원금대비)를 웹·엑셀·요약 3표면에 일관 반영해야 함(누락 시 오독 유발).
- 데이터 D-3(선물/ETF 수급)은 KRX 소스 필드 실측 후 스펙 확정(빈 약속 금지).
