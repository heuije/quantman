# 엑셀 증빙 생성 워크플로우 재설계 (`ir_engine/excel_export.py`)

## 0. 배경 · 문제

챗봇 분석 결과를 IB/PE급 **raw data + 라이브 수식** 엑셀로 증빙(#1, PR#172/#179). 라이브 검증에서
**신호종목(S&P500) 가격이 워크북에 아예 없어** 전략 핵심(신호→포지션) 수동검증이 불가한 결함 발견.

### 근본 결함 2겹 (단건 아닌 부류)
1. **출력 주도:** 원자료 시트가 심볼 목록을 `_held_symbols(result)`(=`weight`/`trades`의 **거래·보유 종목**)에서
   가져옴. 신호·팩터·벤치는 **입력이되 거래하지 않으므로** 포지션·거래목록에 없어 누락. S&P500 누락은
   이 부류의 한 사례. → **입력 ⊇ 출력**인데 출력만 봄. (`dataset`엔 신호종목이 멀쩡히 있는데 한 줄 차이로 안 꺼냄.)
2. **문법 부재:** 11개 형상마다 `_build_*` 손수 작성 → 일관성·재사용 없음, 누락·드리프트 불가피.

빈 `일별비중` 시트(단일종목 백테스트는 엔진이 `weight` 패널 미산출)도 같은 "포지션 중심" 가정의 증상.

## 1. 축 1 — 연산작업 유형 (MECE, `result_shape()` 정본 기반)

11개 형상을 **검증체인 모양**으로 6부류로 묶음(모든 형상 포함 = MECE):

| 부류 | 포함 형상 | 계산 본질 | 검증 체인 |
|---|---|---|---|
| **A. 시계열 복리** | `simulate`·`sweep:period_split`·`sweep:condition` | 신호→포지션→일손익→복리 | 입력 시계열 → 일별 수식 → 자산 → 지표 |
| **B. 변형 스윕** | `sweep:parameter`·`sweep:asset` | A를 N회(변형축) | 변형값별 A + 버킷 대조 |
| **C. 횡단 랭킹** | `select`·`extremize` | as-of 점수→정렬/선택 | 개체별 입력→점수식→순위 |
| **D. 개체 특성화** | `describe_single`·`describe_portfolio` | 한 개체/포트 집계통계 | 개체 입력→통계식 |
| **E. 통계 관계** | `relate_ic`·`relate_regression`·`event_study` | 신호↔미래수익 패널통계 | 패널(날짜×개체)→IC/회귀/전후 |
| **F. 원시 조회** | `inspect` | 시계열 그대로 | 원시값 = 산출물 |

## 2. 축 2 — 데이터 입력 역할 (MECE, 계산상의 역할로 5분류)

| 역할 | 무엇 | 출처 | 현 상태 |
|---|---|---|---|
| **① 대상(Subject)** | 거래·분석 대상 OHLCV | `universe.symbols` | 종가만(개선 필요) |
| **② 신호·팩터(Signal)** | 결정 구동 참조 시계열·파생지표 | `dataset` − subject (신호 참조) | **누락(핵심 결함)** |
| **③ 참조(Reference)** | 벤치·섹터·펀더멘털 | 엔진 파생/`needed_columns` | 부분 |
| **④ 파라미터 공간(Param)** | 스윕값·후보별 결과 | `study`/`objective` | 결과만 |
| **⑤ 실행 가정(Exec)** | 수수료·슬리피지·체결·자본 | `simulation` | ✅(지표·설명) |

> **핵심:** "검증용 raw data" = 입력(①+②+③). 현 코드는 ①(거래된 것)만. 빠진 ②가 신호종목.
> `dataset`은 엔진이 `needed_symbols`(=universe ∪ 신호참조)로 적재 → **dataset − universe = 신호종목**.

## 5. 검증 깊이 L1 / L2 + **L2 충실도 경계** (중요)

- **L1 (집계검증):** 엔진 정본 자산곡선(B열) 위에 일수익·낙폭·CAGR·샤프를 정의식으로. bps=0이면 엔진과 일치. *현행·전 유형 가능.*
- **L2 (로직검증):** 신호→포지션 **결정**을 입력에서 셀로 재현(지표 산술은 정확) + 거래로그 P&L 셀 재계산.

### ⚠ L2가 셀로 byte-match 복제 **불가**한 부분 (코드 확인)
엔진 NAV는 **상태기반 루프**: 정수주·현금·진입/청산·다중 청산룰(익절·손절·ATR·트레일·보유기간)·
이연체결(`defer`)·선물 증거금 사이징, 그리고 신호→체결 **`delay`**(run.py가 목표가중치를 delay만큼 시프트해 실집행).
→ **임의 전략의 자산곡선을 셀 수식으로 정확 재현 불가.** 억지로 하면 셀-엔진 불일치 = 신뢰 훼손.

**따라서 L2 = "결정 로직 독립 재현 + 거래 P&L 검증"까지, 자산곡선 자체는 L1 유지.**
신호값 지표(pct_change 등)는 **순수 산술이라 정확** → 셀 재현 OK. 단 **체결 타이밍(delay)은 엔진 소관**이므로
신호 패널은 "독립 재현(엔진 실집행은 거래내역 참조)"로 라벨링 — 오해 방지.

## 6. 적용 범위 · 단계 (승인: **시계열복리 우선 + L2 추구**)

### Phase 1 — 입력 주도 코어 (위험 0, 즉시) ✅ 이번 구현
- `_input_symbols_by_role(ir, dataset)`: 출력(`_held_symbols`) → **입력**(`dataset` − universe = 신호). subject/signal 분리.
- **원자료 → 입력데이터**: 대상 **OHLC**(거래·마킹 기준) + 신호 **종가**(결정 입력), 역할 라벨. → S&P500 등장.
- **빈 일별비중 생략**: `weight` 패널 없으면 시트 미생성(죽은 시트 제거).
- 효과: 신호종목 raw 등장 → 유저가 신호를 **수동** 검증 가능. 순수 raw라 충실도 위험 0.

### Phase 2 — L2 자동화 (신호·결정 패널)
- **IR 신호트리 → Excel 수식 컴파일러**(공통 op: const·data(지표)·compare·select·산술). 미지원 op는
  **우아한 폴백**(패널 생략 + "입력+거래내역으로 검증" 명시 — 잘못된 수식 절대 금지).
- 지원 지표: pct_change_Nd·ts_delay·ts_mean(sma)·momentum 비율·raw OHLC 참조. (RSI 등 복잡지표 폴백.)
- **신호·결정 패널**: 일자별 신호값(라이브)·포지션 룰(중첩 IF) — "독립 재현·체결은 거래내역" 라벨.
- 거래내역에 **가격수익률(비용 전)** 열 추가(엔진 순수익률과 병치 → 차이=비용, 충실도 확보 방식).

### Phase 3 — 타 유형 문법화 (후속)
- C·D·E·F를 S0–S5 primitive로 재작성, 모든 유형에 입력 역할태깅 + 엔진값‖라이브 병치.

## 7. 구현 5원칙
1. **입력 주도:** S1 심볼 = `dataset`/`needed_symbols`(입력), `_held_symbols`(출력) 아님.
2. **문법 조합:** `_build_*` → S0–S5 primitive. 새 연산 = 매핑 한 줄.
3. **엔진값 ‖ 라이브수식 병치:** 모든 결과/지표에 정본값 옆 재계산식.
4. **검증깊이 정직:** 정확히 셀로 되는 것만 라이브(신호 산술·집계). NAV·체결은 엔진 정본 + 명시 경계.
5. **데이터품질 동봉:** S0에 Phase 0.5 경고 표면화(4계층 일관).

## 9. Phase 3 — 유형별 커버리지 감사 (MECE 종결)

전 빌더 감사 결과, 두 원칙(입력 역할태깅·엔진값‖라이브)의 적용 가능성은 유형별로 다름. 작동하는
빌더를 균일성만을 위해 일괄 재작성하는 것은 over-engineering(원칙 2)이라, **유형 특성에 맞는
커버리지**로 종결한다:

| 유형 | 커버리지 | 근거 |
|---|---|---|
| simulate·period_split·condition(단일대상) | **L2**(신호·결정 라이브 + 백테스트 라이브) | Phase 1·2 |
| describe_single | L1+라이브(52주·연변동성 셀 재계산) | 기존 정합 |
| describe_portfolio | L1+라이브(HHI·유효종목·가중PBR 셀‖엔진) | 기존 정합 |
| select | L1(후보×팩터값=입력 노출) | as-of 단면 — 시계열 라이브 무의미 |
| sweep(parameter·asset)·extremize | **값-전용(올바른 한계)** | 각 버킷/후보=독립 백테스트 → 한 시트 라이브 불가 |
| relate(IC·회귀)·event_study | 값-전용 | 원시 패널(날짜×개체)·per-event 미노출 + 대용량 |
| signal_dist | 값-전용+히스토그램 | 원시 신호계열 엔진 미노출(셀 재평가는 결합도↑ — 보류) |

**전 유형 공통(Phase 3 구현):** 데이터 품질·실행 경고(Phase 0.5·무거래)를 **모든 빌더의
'설명/지표' 시트에 표면화**(`_warning_block`) — 데이터 품질 계약이 챗 응답뿐 아니라 엑셀(오프라인
검토)에도 닿는다(원칙 #5).

**결론:** "모든 유형을 같은 시트로"가 아니라 "각 유형이 *검증 가능한 만큼* 라이브, 나머지는 정직하게
값-전용 + 입력·경고 노출"로 종결. 추가 라이브화(per-date IC·per-event·신호계열)는 **엔진이
중간 시계열을 내보낼 때** 가능 — 후속 엔진 과제.
