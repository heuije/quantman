**정본 디자인:** `DESIGN.md`(네이비/골드/차콜·한국식 방향색·mod-std 22/16/12pt·차트 §8)

## 1. 배경 · 문제

두 화면이 "정보 불충분·불친절"하다는 사용자 지적을 코드로 진단(Explore 매핑)한 결과, 실제 문제는
**정보 부족이 아니라 raw 데이터 과다 + 해석 부재 + 우선순위 없음 + 역할 혼선**이었다.

**트레이딩(`/monitor`)** 현행 결함(근거: `web/src/pages/Monitor.tsx`):
- 신호가 **코드 조각**으로 노출(`"MA20 > MA60"`) — 초중급 대상에 부적합(DESIGN 원칙2 위반).
- **방금 구현한 넷팅 절감액이 웹에 미노출**(로컬앱에만). `n_netted`·`commission_saved_krw`는 이미
  스냅샷 `cycle_summary`까지 흘러오나(§5) 렌더 안 됨.
- 정합성 drift가 표 안에 묻힘, 킬스위치·드로다운 경보에 **"다음 조치"** 없음.
- 전략 카드에 **"오늘 실행됐나·언제"** 없음(누적만). **어느 계좌가 실행 중인지** 불명.
- 슬리피지·거부율·체결률·자본곡선(`equity[]`) 데이터가 오는데 미표시.

**내 전략(`/strategies` + `StrategyDetail.tsx`)** 현행 결함:
- 카드 요약이 모호(`"매수 2·매도 3 규칙"`), **"보유 N종목"은 개수만**(수익 여부 없음).
- **라이브 실행 현황(평가금액·손익)과 연구(백테스트)가 한 화면에 혼재** → 역할 불명확.
- 버전 복원 전 diff 없음, 백테스트↔버전 미연결, 계좌 capability 차단 사유가 모달 안에 숨음.

## 2. 핵심 결정 — 두 탭의 역할 분리 (SSOT)

가장 중요한 구조 결정. 사용자 확정:

| | **트레이딩** (`/monitor`) | **내 전략** (`/strategies`) |
|---|---|---|
| **정체성** | 자동매매 **실행 현황** | 자동매매 이전 **전략 연구·관리** |
| **성과 표면** | 라이브 평가금액·손익·전략별 *실행* 기여 | **백테스트 성과만**(CAGR·MDD·샤프) |
| **금지** | — | 라이브 평가금액·손익·보유 표시 금지(→트레이딩) |

이 분리가 두 화면의 정보 우선순위를 결정한다. 라이브 손익·보유·넷팅은 **트레이딩 전용**,
백테스트·설정·버전은 **내 전략 전용**.

## 3. 트레이딩 재설계 (성과 우선)

돈 다루는 도구라 성과를 앞세우되 신뢰·안전을 바로 아래 배치. 계층(위→아래):

1. **① 성과 히어로** — 5초 답. 큰 KPI(누적 수익률 %·금액 · 오늘 손익 · 총 평가금액) + 기간 토글
   (오늘/7일/30일/전체) + **자본곡선**(골드 선; `snapshot.payload.equity[]` — 현재 미사용) +
   한 줄 해석. 방향색 = 한국식(수익 빨강 `--up` / 손실 파랑 `--down`).
2. **② 상태 바(compact)** — 자동매매 칩(실행중/일시정지/정지) · **활성 계좌**(모의/실전 배지) ·
   연결·하트비트(초록/앰버/빨강 + "N분 전") · **다음 사이클 카운트다운**. 평상시 "이상 없음 ✓"
   한 줄, 문제 시에만 경보 확장(킬스위치·드로다운·정합성 drift·고아·US실시간) — **각 경보에
   "다음 조치" 한 줄 + 액션 버튼**.
3. **③ 오늘 활동 (넷팅 하이라이트)** — "오늘 N매수·M매도 · **넷팅 K건으로 수수료 ~X원 절약**"
   카드 + 각 거래 평문화(`"삼성전자 10주 매수 — '단기추세>장기추세' 신호 충족"`; 코드조각은
   `title` 툴팁으로 원문 보존).
4. **④ 전략별 성과 기여** — 카드: 손익(오늘/7일/30일/누적·방향색)·승률·**오늘 실행됨✓/언제**·
   보유수+평균수익·다음 예정매매(평문). 기여 큰 순 정렬. (라이브 P&L은 여기 = 실행 현황)
5. **⑤ 보유 종목** — 파이(**네이비/골드 토큰으로 교체** — 현행 하드코딩 PIE_COLORS 제거) +
   표(수익률 정렬; drift는 ②경보로 승격).
6. **⑥ 감사·로그(접힘)** — 미체결·최근주문·사이클·명령: collapsible, 파워유저용. CSV export 유지.

### 3.1 데이터원 (전부 기존 스냅샷 — 서버 무변경)
`snapshot.payload`: `balance`·`equity[]`·`positions[]`·`strategy_pnl`(today/week/month/pnl)·
`cycle_summary`(+ `n_netted`·`commission_saved_krw`)·`kill_switch`·`drawdown`·`health`
(account_handles·active_account_ids)·`next_day_preview`(signal_passed)·`reconciliation`·`auto_status`.

## 4. 내 전략 재설계 (백테스트 전용)

### 4.1 목록 (`/strategies`)
- 헤더 + 필터 탭(전체/연동됨/모의/초안, 카운트). **라이브 롤업 없음.**
- **건강 스캔형 카드**: 전략명 + 상태 배지(연동됨/모의/초안) + **대상 평문**(`"코스피200선물"` +
  조건 칩 — `"매수2·매도3"` 대체) + **백테스트 KPI 4칸**(총수익·CAGR·MDD·샤프; 방향색) +
  메타(백테스트 기간·버전·마지막 실행일) + 액션. 백테스트 미실행 시 "백테스트 실행" CTA.
- 연동된 전략은 **"실행 현황은 트레이딩 →"** 링크(손익 숫자는 표시 안 함).

### 4.2 상세 (`/strategies/:id`)
탭: **설정값 · 버전 · 백테스트 내역** (라이브 "현황" 탭 제거 → 트레이딩).
- **상단**: 대표 백테스트 성과 요약 + **실전 연동 준비도** 배지(백테스트 기준: 충분한 기간·MDD·
  샤프 → "연동 권장") + **[트레이딩 연동]** 액션.
- **설정값**: 평문 한 줄 요약 + `SentenceTree`(유지) + **"오늘 신호 통과✓/미충족"**
  (`next_day_preview` 교차참조) + 백테스트 가정(수수료·슬리피지·기간·초기자본) 명확.
- **버전**: 각 버전 → **diff 뷰**(정의 필드가 이미 있어 클라이언트 diff; 복원 전 무엇이 바뀌는지).
- **백테스트 내역**: 각 run(총수익·MDD·샤프·기간) + **버전 링크** + (있으면) 백테스트↔실전 갭은
  트레이딩 링크로.
- **계좌 연동 설정**(AccountBindingSection)은 여기서 setup 시작 + **capability 차단 사유 페이지
  선표시**(모달 열기 전). 연동 후 실행 손익은 트레이딩.

## 5. 넷팅 웹 표시 — 서버 무변경 확인

서버는 스냅샷 payload를 JSON 통째 저장·조회하고 `cycle_summary`를 passthrough
([`sync.py:170`](../../server/app/routers/sync.py)) → 로컬이 넣은 `n_netted`·`commission_saved_krw`가
**이미 웹 스냅샷까지 도달**. 웹 변경만 필요:
- `web/src/types.ts` `CycleSummary`에 `n_netted?: number`·`commission_saved_krw?: number` 추가.
- 트레이딩 ③에서 렌더(값>0일 때 카드, 0이면 조용히 생략).

## 6. 디자인 시스템 준수 (DESIGN.md)

- 색은 토큰만(`--up`/`--down`/`--accent`/`--panel`/…), **임의 hex·회색 위젯 금지**. 방향성 숫자 =
  한국식(수익 빨강/손실 파랑), 상태 = green/red/amber, 강조 = 골드.
- 차트 §8: 자본곡선 = **골드 선**, 파이 = 네이비 계열(하드코딩 PIE_COLORS 교체), 등장 애니 없음.
- 타이포: mod-std 22/16/12pt, tabular-nums, 배수 `x`·금액 콤마.
- 컴포넌트: `.panel`·`.stat`·`.tabs`·`.chip`·`.badge`·정보아이콘(전문용어 툴팁)·빈 상태(제목+안내+CTA).

## 7. 데이터 가용성 — 착수 시 확인(과대약속 방지)

| 요소 | 상태 | 없을 때 대체 |
|---|---|---|
| 자본곡선(`equity[]`) | 스냅샷에 존재 | — |
| 넷팅(`n_netted`·`commission_saved_krw`) | cycle_summary로 도달(§5) | 값 없으면 카드 생략 |
| 전략별 오늘/주/월 손익 | `strategy_pnl` 존재 | — |
| **벤치마크 비교("코스피 대비")** | **미확인** | 없으면 "누적 해석"만 |
| **월별 손익 히스토리** | **미확인**(today/week/month만 있을 수 있음) | 주/월 3칸 요약 |
| 오늘 신호 통과 | `next_day_preview.signal_passed` 추정 | 없으면 생략 |
| 버전 diff | 정의 필드 존재 → 클라이언트 diff | — |

## 8. 비목표 (YAGNI)

- **서버·엔진 변경 없음.** 기존 스냅샷 데이터만 사용(넷팅 포함). 새 엔드포인트 도입 지양.
- 포트폴리오 상관·섹터 노출 등 신규 분석(별 트랙).
- 내 전략에 라이브 손익 재도입(역할 분리 위반).
- 새 색/폰트/간격 도입.

## 11. 리스크 · 미해결

- **벤치마크·월별 히스토리 데이터 부재 가능**(§7) — 없으면 축소 렌더(설계에 대체안 명시됨).
- 라이브 스냅샷은 로컬앱 연동·실행이 있어야 채워짐 → 미연동 사용자엔 트레이딩이 대부분 빈 상태
  (성과 히어로도) → **온보딩 빈 상태**(페어링 유도)를 성과 히어로 자리에 우선 표시.
- 담당 경계: 웹 빌더·시각화는 공통(조대표), 포트폴리오·개별종목 화면은 희제. 트레이딩·내 전략은
  자동매매 표면(조대표)이나 겹치면 협의.
