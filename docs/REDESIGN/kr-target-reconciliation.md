## 1. 왜 (문제)

지금 주문 생성은 **증분 + 클램프 + 넷팅 + commingling 정합**의 패치워크다. 07-14 mwmw 사고가 이 복잡도의 결함을 한꺼번에 드러냈다:

- **넷팅 book handoff**가 stale 참조가로 정산 → phantom 실현손익 +120.5M/−41.9M (A2).
- **§2 잔여청산이 snap_pre 재사용** → 넷팅 소비 재고 이중계상 → 불필요 실매도(order 355) (A3).
- **수동매매(9계약 순매도)와 자동이 한 계약에 얽힘** → 원장↔브로커 drift +5, 의도외 오버나이트 노출 (commingling C1).
- capacity_credit·여력원장 등 부수 기계가 각자 재고를 계산 → 이중계상 잠복.

근본은 **"각 전략이 증분 주문을 내고 브로커에 클램프"** 라는 모델 자체다. 재고가 여러 곳에서 독립 계산되니 정합이 깨진다.

## 2. 모델 — 목표상태 수렴

**원장(전략 의도) = 목표. 매 사이클, 심볼별로 브로커를 목표로 수렴시키는 단일 순주문을 낸다.**

```
매 사이클, 각 심볼:
  target_qty   = 이 사이클 후 autotrade가 의도하는 순 포지션 (전략 원장의 심볼별 합, 방향 부호)
  broker_qty   = 브로커 실보유 (수동매매 포함 — account_snapshot)
  net_order    = target_qty − broker_qty        # 부호: +매수 / −매도
  → net_order 하나만 발주 (fresh 참조가로)
```

`net_order`는 **"autotrade가 넣어야 할 거래" + "수동 drift 교정"을 하나로 흡수**한다. 수동매매를 되돌리는 별도 주문을 내지 않고 netting된 단일 주문만 나간다(조대표 refinement). 결과: 브로커는 매 사이클 **autotrade-only 포지션**에 수렴.

### 핵심 성질
- **넷팅은 공짜**: #27 진입 + #29 청산이 같은 심볼이면 target에서 자동으로 상쇄된다(book handoff 불필요).
- **수동매매 자동 흡수**: 수동 drift는 broker_qty에 반영돼 net_order로 교정된다. 별도 정합 로직 불필요.
- **오버셀 불가**: target은 롱 의도 합 ≥ 0. broker>target이면 초과분 매도(flat까지, 숏 안 감). target<broker면 클램프 자연 발생.

## 3. 핵심 설계 결정

### 3.1 전략별 P&L 귀속 (순주문은 aggregate인데 손익은 전략별)
- **원장 = per-strategy 의도(진실)**. 각 전략의 진입/청산은 원장에서 개별 booking(진입가·실현손익)하고, `net_order`는 그 합을 브로커에 물리 반영한다.
- 지금 넷팅 정산(`_apply_netted_leg`)과 같은 구조를 **항상** 적용: 상쇄되는 부분은 book(전략간 이관), 잔여만 실 net_order. 차이는 "이제 예외가 아니라 기본 경로".

### 3.2 정산 참조가 = fresh 단일가 (Phase 0 통합점)
- 각 전략 변화를 booking하는 가격 = **심볼·사이클당 단일 fresh 참조가**. stale이면 phantom(07-14). → **Phase 0 신선도 게이트가 이 참조가 무결성을 보장** = 목표모델에 그대로 통합.
- 넷팅 양다리(#27 진입·#29 청산)가 같은 fresh 가격에 정산되므로 phantom 구조적 소멸(A2가 특수케이스에서 일반원리로 승격).

### 3.3 사이징 기준 — **미해결(결정 필요)**
target_qty의 크기를 무엇으로 정하나:
- **(a) 라이브 orderable**: 브로커 현재 주문가능수량. 단순하나 수동매매가 자본을 바꾸면 target 크기도 바뀜(순수 autotrade-only 아님).
- **(b) autotrade 자본원장**: autotrade 몫의 자본을 따로 추적 → 순수 autotrade-only. 정확하나 복잡.
- **(c) 진입 시점 1회 사이징 후 고정**: 포지션 열 때 사이징(라이브 orderable)해 원장 target 고정, 청산까지 유지. 수동 drift는 그 고정 target으로 수렴. **← 권장(단순+의도 보존)**.

## 13. 🔴 필수 규칙 — "목표 없음 ≠ 목표 0" (적대검토 catch)

**함정**: 순진한 구현이 "이 심볼 목표를 못 정함"을 `target=0`으로 처리하면, **stale 데이터·에러가 전량 청산을 유발**한다(07-14보다 위험한 신규 버그). 예: 07-14 종가에 데이터 stale → #27 목표 미정 → 0으로 오인 → 청산.

**규칙 — `target=0`(청산)과 `target=미정`(hold)을 반드시 구분한다:**

| 상황 | 목표 | 행동 |
|---|---|---|
| 전략 없는 심볼(고아·수동 보유) | **0** | 청산(§9 ③) |
| 전략 有 · **명시 청산**(exit 규칙 발동) | **0** | 청산 |
| 전략 有 · **fresh 신호** | 신호값 | 수렴(net_order) |
| 전략 有 · **stale/에러/신호불가** | **미정(None)** | **hold — 이 심볼 이번 사이클 수렴 skip**(청산 아님) |

**구현 계약(T1)**: 목표 산출기는 심볼별로 `int | None`을 반환한다 — `None`은 "판정 불가=현상 유지". T2 순주문 엔진은 `target is None`이면 그 심볼을 건너뛴다(net_order 미생성). `target=0`일 때만 청산.

**신선도 상호작용(A1)**: 진입 사이징 가격이 stale이면 → 목표 `None`(진입 skip=fail-closed, 기존 보유 hold). 청산 가격은 live(fail-open)라 명시 청산은 stale에도 진행. 즉 **stale는 "새 진입만 막고 기존은 건드리지 않는다".**

## 14. 제거 가능 규칙 vs 더 중요해지는 규칙

목표모델("실보유에서 net 역산")이 통일하면서 아래가 **잉여로 제거**된다:
- **oversell clamp**(`clamp_sell_qty`): 매도량 = `broker − target` ≤ broker (target≥0)이라 net 공식에 내장. 실보유에서 역산하니 오버셀 불가능.
- **넷팅**(`net_window`·book_legs·`_apply_netted_leg`): 같은 심볼 target 상쇄가 곧 넷팅.
- **§2 잔여청산 + snap_pre 클램프**(A3): net이 청산 흡수.
- **capacity_credit·`_freed_capacity`**(E1): 사이징에 내재.
- **netted_opener_sids wash-sale 가드**: §2 부재로 "방금 연 걸 재청산" 불가능.
- **skip_oversell 결정·부분클램프 로깅**: net이 자연 처리.
- **진입/청산 2패스(§2/§3) 분리**: 단일 패스(target→net)로 통합.
- **reconcile drift *교정*(ledger←broker)**: 방향 역전 — 브로커가 원장 따라감. external_extras 교정 불요(관측용 telemetry는 유지 가능).

**반대로, 더 중요해지는(유지·강화):**
- 🔴 **pending 멱등**: `net = target − (broker + pending)`. pending 미차감 시 이전 발주 체결 전 재발주 → **이중발주**. clamp 대신 이게 목표모델의 핵심 안전선.
- **정확한 브로커 조회**: net이 `account_snapshot` 정확성에 전적 의존. 조회 실패/부분 → 데이터 가용성 가드(skip) 필수.
- **intraday 손절/킬스위치**: 연속·live 리스크 가드로 잔존("보유 전량 청산"이라 오버셀 무관).

**순효과**: 주문 생성 코어가 "패치워크 5겹"→"net = target − broker" 한 줄. 안전선이 clamp(사후 보정)에서 pending 멱등(사전 정합)으로 이동.

## 15.3 협의·수정 필요 (done work 충돌 + 통합점) — 유저 질문의 핵심

**① A1(구현完) → T1로 이관** *(수정 필요)*: 현재 A1은 `_try_buy_one_symbol`(증분 진입)에 있는데, 그 함수가 목표모델 T1로 대체된다. A1의 `_bar_is_stale` 로직은 **유지하되 T1의 목표 산출로 이동**(§13: stale→target None=hold, fail-closed 진입만).

**② A2·A3(구현完) → 제거** *(수정 필요)*: A2(넷팅 정산가)·A3(§2 이중계상)는 넷팅/§2 경로를 고친 것. 목표모델이 그 경로를 **통째 대체**하므로 A2/A3 코드는 삭제(목적 소멸). ⚠️ 그래서 **A1/A2/A3를 지금 단독 릴리스하지 않고 목표모델과 통합**(유저 "통합" 방침과 일치).

**③ 문제12(verify-then-retry) ↔ 목표모델 pending 멱등 = 통합** *(협의)*: 둘이 겹친다. 목표모델의 `net = target − (broker + pending)`가 곧 verify-then-retry 안전판(이중발주 방지). **별도 재시도 기계를 만들지 말고 pending 정합에 통합**. 남는 것은 "창내 즉시 재시도"(선물 개장 좁은 창)뿐 — cross-cycle 재시도는 목표모델이 이미 제공(다음 사이클 net 재계산).

**④ thin-client preview ↔ 목표모델 T1 입력 = 공동설계** *(협의)*: 방향 B의 preview는 **목표모델 T1이 필요로 하는 것**(심볼별 신호·사이징용 가격·청산신호·비전략 판별)을 운반해야 한다. thin-client 스펙 = T1 입력 스펙. **따로 설계하면 안 되고 목표모델이 preview 스키마를 규정**.

**⑤ 신선도 판정 ↔ thin-client = 적응** *(협의)*: 방향 B면 stale 판정 기준이 "번들 마지막 봉 날짜"→"preview 버전/기준거래일"로 바뀐다. A1의 `_bar_is_stale`(봉 날짜)이 thin-client에선 "preview가 오늘 거래일 기준인가"로 대체. **T1의 신선도 계약을 데이터소스 무관하게 추상화**(봉 or preview 버전).

**⑥ 08:35 선물 사이클 ↔ 목표모델 = 시장별 스코프** *(협의)*: 08:35엔 **선물만** 수렴(주식은 08:55). 목표모델 사이클을 **시장/자산군별로 스코프**(이번 사이클 대상 심볼만 target 산출·net). 기존 market batching 재사용.
