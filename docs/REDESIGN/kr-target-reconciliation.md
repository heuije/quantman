## 1. 왜 (문제)

지금 주문 생성은 **증분 + 클램프 + 넷팅 + commingling 정합**의 패치워크다. 07-14 mwmw 사고가 이 복잡도의 결함을 한꺼번에 드러냈다:

- **넷팅 book handoff**가 stale 참조가로 정산 → phantom 실현손익 +120.5M/−41.9M (A2).
- **§2 잔여청산이 snap_pre 재사용** → 넷팅 소비 재고 이중계상 → 불필요 실매도(order 355) (A3).
- **수동매매(9계약 순매도)와 자동이 한 계약에 얽힘** → 원장↔브로커 drift +5, 의도외 오버나이트 노출 (commingling C1).
- capacity_credit·여력원장 등 부수 기계가 각자 재고를 계산 → 이중계상 잠복.

근본은 **"각 전략이 증분 주문을 내고 브로커에 클램프"** 라는 모델 자체다. 재고가 여러 곳에서 독립 계산되니 정합이 깨진다.

## 2. 모델 — 목표상태 수렴

**원장(전략 의도) = 목표. 매 사이클, 심볼별로 브로커를 목표로 수렴시키는 단일 순주문을 낸다.**

```
매 사이클, 각 심볼:
  target_qty   = 이 사이클 후 autotrade가 의도하는 순 포지션 (전략 원장의 심볼별 합, 방향 부호)
  broker_qty   = 브로커 실보유 (수동매매 포함 — account_snapshot)
  net_order    = target_qty − broker_qty        # 부호: +매수 / −매도
  → net_order 하나만 발주 (fresh 참조가로)
```

`net_order`는 **"autotrade가 넣어야 할 거래" + "수동 drift 교정"을 하나로 흡수**한다. 수동매매를 되돌리는 별도 주문을 내지 않고 netting된 단일 주문만 나간다(조대표 refinement). 결과: 브로커는 매 사이클 **autotrade-only 포지션**에 수렴.

### 핵심 성질
- **넷팅은 공짜**: #27 진입 + #29 청산이 같은 심볼이면 target에서 자동으로 상쇄된다(book handoff 불필요).
- **수동매매 자동 흡수**: 수동 drift는 broker_qty에 반영돼 net_order로 교정된다. 별도 정합 로직 불필요.
- **오버셀 불가**: target은 롱 의도 합 ≥ 0. broker>target이면 초과분 매도(flat까지, 숏 안 감). target<broker면 클램프 자연 발생.

## 3. 핵심 설계 결정

### 3.1 전략별 P&L 귀속 (순주문은 aggregate인데 손익은 전략별)
- **원장 = per-strategy 의도(진실)**. 각 전략의 진입/청산은 원장에서 개별 booking(진입가·실현손익)하고, `net_order`는 그 합을 브로커에 물리 반영한다.
- 지금 넷팅 정산(`_apply_netted_leg`)과 같은 구조를 **항상** 적용: 상쇄되는 부분은 book(전략간 이관), 잔여만 실 net_order. 차이는 "이제 예외가 아니라 기본 경로".

### 3.2 정산 참조가 = fresh 단일가 (Phase 0 통합점)
- 각 전략 변화를 booking하는 가격 = **심볼·사이클당 단일 fresh 참조가**. stale이면 phantom(07-14). → **Phase 0 신선도 게이트가 이 참조가 무결성을 보장** = 목표모델에 그대로 통합.
- 넷팅 양다리(#27 진입·#29 청산)가 같은 fresh 가격에 정산되므로 phantom 구조적 소멸(A2가 특수케이스에서 일반원리로 승격).

### 3.3 사이징 기준 — **미해결(결정 필요)**
target_qty의 크기를 무엇으로 정하나:
- **(a) 라이브 orderable**: 브로커 현재 주문가능수량. 단순하나 수동매매가 자본을 바꾸면 target 크기도 바뀜(순수 autotrade-only 아님).
- **(b) autotrade 자본원장**: autotrade 몫의 자본을 따로 추적 → 순수 autotrade-only. 정확하나 복잡.
- **(c) 진입 시점 1회 사이징 후 고정**: 포지션 열 때 사이징(라이브 orderable)해 원장 target 고정, 청산까지 유지. 수동 drift는 그 고정 target으로 수렴. **← 권장(단순+의도 보존)**.

## 13. 🔴 필수 규칙 — "목표 없음 ≠ 목표 0" (적대검토 catch)

**함정**: 순진한 구현이 "이 심볼 목표를 못 정함"을 `target=0`으로 처리하면, **stale 데이터·에러가 전량 청산을 유발**한다(07-14보다 위험한 신규 버그). 예: 07-14 종가에 데이터 stale → #27 목표 미정 → 0으로 오인 → 청산.

**규칙 — `target=0`(청산)과 `target=미정`(hold)을 반드시 구분한다:**

| 상황 | 목표 | 행동 |
|---|---|---|
| 전략 없는 심볼(고아·수동 보유) | **0** | 청산(§9 ③) |
| 전략 有 · **명시 청산**(exit 규칙 발동) | **0** | 청산 |
| 전략 有 · **fresh 신호** | 신호값 | 수렴(net_order) |
| 전략 有 · **stale/에러/신호불가** | **미정(None)** | **hold — 이 심볼 이번 사이클 수렴 skip**(청산 아님) |

**구현 계약(T1)**: 목표 산출기는 심볼별로 `int | None`을 반환한다 — `None`은 "판정 불가=현상 유지". T2 순주문 엔진은 `target is None`이면 그 심볼을 건너뛴다(net_order 미생성). `target=0`일 때만 청산.

**신선도 상호작용(A1)**: 진입 사이징 가격이 stale이면 → 목표 `None`(진입 skip=fail-closed, 기존 보유 hold). 청산 가격은 live(fail-open)라 명시 청산은 stale에도 진행. 즉 **stale는 "새 진입만 막고 기존은 건드리지 않는다".**

## 14. 제거 가능 규칙 vs 더 중요해지는 규칙

목표모델("실보유에서 net 역산")이 통일하면서 아래가 **잉여로 제거**된다:
- **oversell clamp**(`clamp_sell_qty`): 매도량 = `broker − target` ≤ broker (target≥0)이라 net 공식에 내장. 실보유에서 역산하니 오버셀 불가능.
- **넷팅**(`net_window`·book_legs·`_apply_netted_leg`): 같은 심볼 target 상쇄가 곧 넷팅.
- **§2 잔여청산 + snap_pre 클램프**(A3): net이 청산 흡수.
- **capacity_credit·`_freed_capacity`**(E1): 사이징에 내재.
- **netted_opener_sids wash-sale 가드**: §2 부재로 "방금 연 걸 재청산" 불가능.
- **skip_oversell 결정·부분클램프 로깅**: net이 자연 처리.
- **진입/청산 2패스(§2/§3) 분리**: 단일 패스(target→net)로 통합.
- **reconcile drift *교정*(ledger←broker)**: 방향 역전 — 브로커가 원장 따라감. external_extras 교정 불요(관측용 telemetry는 유지 가능).

**반대로, 더 중요해지는(유지·강화):**
- 🔴 **pending 멱등**: `net = target − (broker + pending)`. pending 미차감 시 이전 발주 체결 전 재발주 → **이중발주**. clamp 대신 이게 목표모델의 핵심 안전선.
- **정확한 브로커 조회**: net이 `account_snapshot` 정확성에 전적 의존. 조회 실패/부분 → 데이터 가용성 가드(skip) 필수.
- **intraday 손절/킬스위치**: 연속·live 리스크 가드로 잔존("보유 전량 청산"이라 오버셀 무관).

**순효과**: 주문 생성 코어가 "패치워크 5겹"→"net = target − broker" 한 줄. 안전선이 clamp(사후 보정)에서 pending 멱등(사전 정합)으로 이동.

## 15.3 협의·수정 필요 (done work 충돌 + 통합점) — 유저 질문의 핵심

**① A1(구현完) → T1로 이관** *(수정 필요)*: 현재 A1은 `_try_buy_one_symbol`(증분 진입)에 있는데, 그 함수가 목표모델 T1로 대체된다. A1의 `_bar_is_stale` 로직은 **유지하되 T1의 목표 산출로 이동**(§13: stale→target None=hold, fail-closed 진입만).

**② A2·A3(구현完) → 제거** *(수정 필요)*: A2(넷팅 정산가)·A3(§2 이중계상)는 넷팅/§2 경로를 고친 것. 목표모델이 그 경로를 **통째 대체**하므로 A2/A3 코드는 삭제(목적 소멸). ⚠️ 그래서 **A1/A2/A3를 지금 단독 릴리스하지 않고 목표모델과 통합**(유저 "통합" 방침과 일치).

**③ 문제12(verify-then-retry) ↔ 목표모델 pending 멱등 = 통합** *(협의)*: 둘이 겹친다. 목표모델의 `net = target − (broker + pending)`가 곧 verify-then-retry 안전판(이중발주 방지). **별도 재시도 기계를 만들지 말고 pending 정합에 통합**. 남는 것은 "창내 즉시 재시도"(선물 개장 좁은 창)뿐 — cross-cycle 재시도는 목표모델이 이미 제공(다음 사이클 net 재계산).

**④ thin-client preview ↔ 목표모델 T1 입력 = 공동설계** *(협의)*: 방향 B의 preview는 **목표모델 T1이 필요로 하는 것**(심볼별 신호·사이징용 가격·청산신호·비전략 판별)을 운반해야 한다. thin-client 스펙 = T1 입력 스펙. **따로 설계하면 안 되고 목표모델이 preview 스키마를 규정**.

**⑤ 신선도 판정 ↔ thin-client = 적응** *(협의)*: 방향 B면 stale 판정 기준이 "번들 마지막 봉 날짜"→"preview 버전/기준거래일"로 바뀐다. A1의 `_bar_is_stale`(봉 날짜)이 thin-client에선 "preview가 오늘 거래일 기준인가"로 대체. **T1의 신선도 계약을 데이터소스 무관하게 추상화**(봉 or preview 버전).

**⑥ 08:35 선물 사이클 ↔ 목표모델 = 시장별 스코프** *(협의)*: 08:35엔 **선물만** 수렴(주식은 08:55). 목표모델 사이클을 **시장/자산군별로 스코프**(이번 사이클 대상 심볼만 target 산출·net). 기존 market batching 재사용.

## §16.2 🔴 사이징 정밀도 갭 (2026-07-15 정정 — 앞선 오진 교체)

**근본 원인 (통합)**: 목표모델은 target을 `orderable_qty`(현재 보유 대비 *추가* 여력)로 잰 뒤 `net = target − broker`로 보유를 또 뺀다 → **현재 보유가 두 번 계산**된다. 자동매매 *자기* 청산은 capacity_credit가 보유분을 되돌려 상쇄(정확)하지만, **원장 밖(수동/외부) 보유는 크레딧이 없어** 이중계산이 노출된다:

| 케이스 | 방향 | 결과 | 안전성 |
|---|---|---|---|
| 원장 밖 보유 + **같은 방향** 진입 | orderable(buy)가 보유 제외 → net이 또 뺌 | **과소**(보유량만큼) | 보수적·안전 |
| 원장 밖 보유 + **반대 방향** 진입(부호뒤집기) | orderable(sell)가 청산분 포함(가능성) → net이 또 뺌 | **과대**(가능) | 브로커 증거금 판정이 최종 차단 |

**정정**: 앞서 "교차-심볼 크레딧 이중계상→과대"라 한 건 **오진**이었다. 크레딧은 심볼별이라 **교차-심볼은 크레딧 0 → 보수적 과소활용(안전)**이지 과대가 아니다. 진짜 위험은 위 표 두 행(원장 밖 보유 × 진입 방향).

**손익 처리는 정상**: 청산 손실은 선물 실시간 평가로 현재 자본·orderable에 이미 반영 → 손실로 인한 과대진입 없음(Q-1-1-a).

**해결 = 「빈 상태 사이징」(§18)**: 진입 심볼의 **브로커 실보유 전체를 사이징에서 되돌려**(같은 방향=더함) target을 "수동 취소 후 빈 잔고 기준 최대 크기"로 만든다 — 유저 핵심 원칙(Q-1-1-b)의 정확 구현. **같은 방향은 구현·검증 가능**(§18·`fix/flat-capacity-sizing`), **반대 방향(부호뒤집기)은 `orderable_qty(sell)` 반환 의미가 미검증**이라 개장 모의 실측 후 확정.

→ **릴리스 후 개장 모의 왕복 ×2브로커(LS·KIS)로 `orderable_qty` 의미 실측**. C11 target_convergence·drift_deferred로 프로덕션 관측. mwmw 현 전략(양쪽 롱·수동은 매도)엔 과대 미해당.

**검증 원칙**: E1~E9는 코드+테스트로 이 세션에서 실측, E10~E12는 서버 테스트+배포 후 prod 실측(배포는 유저 허락 필요), E13~E14는 테스트로 실측(실개장 실측은 릴리스 후 아침 게이트), E17은 후속 트랙.

# 18. 「빈 상태 사이징」(flat-capacity sizing) — §16.2 갭 근본수정

> 상태: 설계+같은방향 구현(`fix/flat-capacity-sizing`·검토중). 유저 핵심 원칙(Q-1-1-b) 정확 구현. 배포는 승인·실측 후.

## 18.1 원칙 (유저 정의)
> 유저가 언제 어떤 수동매매를 하더라도, 자동 발주 시 **수동매매를 전부 취소(청산)한 잔고로 자동매매한 결과**를 목표 포지션으로 삼고, 도달엔 **불필요 매수/매도 없이 순거래만** 한다.

- **순거래만(도달)**: 이미 완전 구현(`net = target − broker`·넷팅). ✅
- **목표 크기 = 취소 후 빈 잔고 기준 최대**: 사이징을 **"그 심볼에 아무 것도 안 든 상태의 여력"**으로 재야 한다. 현재는 "보유 든 채의 추가 여력(orderable)"으로 재서 §16.2 이중계산 갭.

## 18.2 수정 — 진입 심볼 브로커 실보유를 사이징에서 되돌림
사이징 크레딧 기준을 **"계획된 청산분(exit_intents)"에서 "진입 심볼의 브로커 실보유 전체(같은 방향)"로 확장**한다. 그러면 orderable + 되돌린 보유 = 빈 상태 여력 → target 정확 → net이 한 번만 빼서 최종 정확.

- **같은 방향 보유**(롱 보유 + 롱 진입 등): 크레딧 = |브로커 보유(같은 side)|. orderable에 더함 → 빈 상태. **구현 대상.**
- **반대 방향 보유**(롱 보유 + 숏 진입=부호뒤집기): `orderable_qty(sell)`이 롱청산분을 포함하면 빼야 하고, 순수 숏여력이면 그대로. **반환 의미 미검증 → 개장 실측 후 확정. 이번 수정은 건드리지 않음(과대 미악화 보장).**

## 18.3 구현 (side-aware 크레딧)
- `_freed_capacity`: 크레딧 dict를 **(symbol, side)별**로 반환(기존 symbol-only → side 인지). 롤 케이스 무회귀(청산·진입 같은 side).
- `_reconcile_pass`: exit_intents 기반 크레딧에 더해, **원장 밖 브로커 보유**(broker held − 계획청산, 같은 side)를 합성 크레딧으로 추가.
- `_try_buy_one_symbol`: 크레딧을 **(symbol, 진입 side)**로 조회 — 진입 side와 다른 보유의 크레딧은 적용 안 함(부호뒤집기에 오적용·악화 방지).
- 다중 진입 순차 소진(decrement) 유지(E2·N9).

## 18.4 검증 (TDD)
- 같은방향 수동보유 → target = 빈상태 최대(과소 해소). 롤(자동 자기청산) 무회귀. 부호뒤집기 → 크레딧 미적용(과대 미악화). 다중진입 순차소진. 전체 골든/시나리오 green.
- **미해결(실측 대기)**: 부호뒤집기 과대 — `orderable_qty(sell)` 의미 개장 실측 후 별도.

# 17. 구현 노트 — 구현 중 확정된 설계 정정 (2026-07-15, Phase 2 구현 세션)

구현·적대 테스트가 설계 원안의 결함/과단순화를 4건 발견해 정정했다. **코드가 정본** — 이 문서의 이전 §과 어긋나면 §17이 우선.

### 17.1 pending 산술 기각 → intent 저널 멱등 (§14 정정)
`net = target − (broker + pending)` 산술은 **기각**. in-flight 주문의 leg는 L-01 멱등 게이트가 재계획에서 빼는데 pending 산술만 남으면 **자기 주문을 상쇄하는 워시 주문**이 나간다(미체결 매수 6 존재 → net −6 매도). 확정 구현:
- **plan-time**: in-flight(활성 intent) 주문이 있는 심볼 → indeterminate(이번 사이클 hold).
- **submit-time**: 전 발주가 intent 저널 게이트 통과(L-01 + 신규 `DRIFT:{window}` 키).
저널은 fsync·크래시 재기동 복구(reconcile_submitting)까지 검증된 기존 기계다.

### 17.2 capacity_credit 유지 (§5·§14 제거 판정 정정)
capacity_credit는 물리 주문 기계가 아니라 **사이징 입력**이다. 제거하면 같은 사이클 롤(A청산+B진입·자본 잠김)에서 B가 0으로 사이징돼 핸드오프가 실매도로 퇴화한다(테스트 실증). **유지**하되 신규 규칙: 크레딧은 **브로커 실보유로 클램프한 청산량만**(수동 선매도분은 이미 브로커 현금/orderable에 반영 — 크레딧하면 이중계상, N7 유지).

### 17.3 "단일 순주문" → "단일 순방향" (§2 구현 형태)
물리 주문은 잔여 leg별 + drift 교정으로 **분할 발주**한다(전부 같은 방향 = sign(net)). 불변식은 "심볼당 단일 순방향"(매수·매도 동시 불가 = 오버셀·wash 소멸)이고, leg별 분할은 기존 `_apply_fill` 회계(전략별 P&L·부분체결·WS 경로)를 무수정 재사용하기 위함. drift 주문은 `pending["drift"]=True`로 **체결돼도 원장 불변**.

### 17.4 A2 fail-open 개정 — stale ref는 정산가 금지 (§13 신선도 정밀화)
구 A2는 "청산은 live 우선, live 없으면 stale이라도 진행(fail-open)" — 구 모델의 ref는 시장가 주문 참고값이라 무해했다. 목표수렴에선 **ref가 정산가**(book leg 실현손익 기장)가 되므로 stale 봉(1210.5)으로 book하면 phantom 재발(적대 테스트 실증). 확정: **청산 정산가 = fresh 봉 or live. 둘 다 없으면 hold**(§13 indeterminate — 다음 사이클 재시도).

### 17.5 부분 스냅샷 degrade — 보유 심볼 hold·신규 진입만 (§14 가용성 가드 구체화)
`fetch_failed` 시 보유가 얽힌 심볼(원장·브로커)은 전부 hold: 원장 전량 청산은 오버셀(의도외 숏), drift 교정은 오인 청산 위험. 보유 무관 신규 진입만 진행(구 모델 가용성과 동일).

### 17.6 reconcile 관측 전용 전환 (§14 이행 완료)
`reconcile_with_kis`의 orphan 자동 차감(ledger←broker) **전면 제거** — 표면화만. 원장=전략 의도 정본, 물리 복원은 다음 사이클 `_reconcile_pass` drift 교정(broker←ledger). 구 I3(주식 자동 차감)도 폐기.

# 19. 동시호가 pending-aware 넷팅 + 개장후 수렴 (수동매매 호환성 개선, 2026-07-16)

**목표 (유저 정의):** "언제 어떤 수동매매를 진행하더라도, 장전·장마감 동시호가 직후에는
자동매매로만 계좌를 운용하는 것과 동일한 포지션으로 교정된다"(자동 발주 08:35·15:40).

## 19.1 문제 — 08:35/15:40 발주 시 수동 pending으로 잔고 오염

동시호가 창(08:30~45·15:35~45)에 유저가 수동매매를 발주하면 그 주문은 **미체결(pending)**
상태로 08:45/15:45에 체결된다. 08:35/15:40 자동 발주 시점엔:
- pending이 증거금/현금을 **예약** → `orderable`·`cash` 축소(사이징 오염 → 자동이 과소 발주).
- pending이 `positions` 스냅샷엔 없음(아직 미체결) → net이 이를 못 보고 **과매수**(체결 후 08:45에 target 초과).

§18(빈-상태 사이징)은 **체결된** 수동 보유만 되돌린다 — pending은 미반영. 그래서 pending을
넷팅·사이징에 반영하는 A1 넷팅이 필요하다.

## 19.2 설계 — 두 계층 (A1 주 + 개장후 수렴 안전망)

**A1: 08:35/15:40 pending-aware 넷팅 (같은 방향만).**
- **외부(수동) pending 식별**: `external = broker.pending_orders() − 자기 order_no`
  (자기 = `intents._read_today()`의 mark_submitted order_no). 이중 방어: 자기 in-flight
  심볼은 이미 `indeterminate` hold(§17.1) → 08:40/42 재시도가 자기 주문을 상쇄하는 워시 차단.
- **effective_current = positions + 외부 pending** (같은 방향·|pending|≤|intended_net| 한도):
  - 넷팅: `broker_signed[key] += 같은방향_capped(외부 pending)` → `net = target − effective_current`.
  - 사이징: 그 pending의 예약 여력을 §18 `extra_capacity`에 되돌림(같은 side) → target = 빈 상태.
  - **단일 순방향 보존**: pending 포함량을 `|intended_net|`로 cap → net 부호가 뒤집히지 않음
    → 자동 net이 수동과 **반대 방향이 되지 않음**(같은 계좌 자전거래·증거금 상충 구조적 회피).
- **반대 방향·초과·교차-종목 pending**: A1에서 **제외**(넷팅·크레딧 안 함, 보수적) → 19.2 안전망이 처리.

**개장후 수렴 (안전망, 방향 무관).** 동시호가 체결(선물 08:45·주식 09:00) 반영 후
`run_cycle` 재실행으로 **실체결 기준 멱등 수렴**(`net = target − broker`):
- 선물 **08:52** · 주식 **09:05** (기존 08:35/08:55 사이클과 별개 cron).
- 잡는 것: A1 취소-race(08:35 넷팅 후 취소)·늦은 수동(08:35 후 발주)·A1 제외분(반대/초과/교차).
- 멱등(L-01 재진입 차단·drift만 교정)이라 무결(교정할 것 없으면 no-op).
- **마감측 불가**: 선물 15:45·주식 15:30 체결 = 시장 마감 → 당일 교정 불가, 익일 개장 carry(원리적 한계).
