# 발주창 넷팅 (Cross-Strategy Order Netting) 설계

**작성:** 조대표 · 2026-07-02
**모듈:** 자동매매 엔진 (`local/localapp/`, 서버 `routers/trading.py`, 웹 트레이딩 탭)
**상태:** 설계 승인 → 구현 계획 대기

---

## 1. 문제

당일매매 전략과 오버나이트 롱 전략을 **같은 선물**(예: 코스피200선물)에 함께 연동하면,
반대 방향 주문이 같은 발주창에 겹쳐 **불필요한 왕복 수수료·슬리피지**가 발생한다.

대표 시나리오 — 두 전략:
- **전략 A** (S&P500 역추종 당일매매): S&P 하락일 → 코스피 선물 시가매수·종가매도(롱),
  상승일 → 시가매도·종가환매(숏). `direction=long_short`, `fill=next_open`, `hold_days=0`.
- **전략 B** (오버나이트 롱): 항상 종가매수 → 익일 시가매도. `fill=close`, 익일 시가청산.

**S&P 하락일**엔 두 발주창 모두에서 왕복이 생긴다:

| 발주창 | 청산(전략) | 진입(전략) | 결과 |
|---|---|---|---|
| 종가 (15:40) | A 롱 **매도** | B 롱 **매수** | 같은 선물 팔고 즉시 삼 = 왕복 낭비 |
| 익일 시가 (08:55) | B 롱 **매도** | A 롱 **매수** | 같은 선물 팔고 즉시 삼 = 왕복 낭비 |

상승일엔 종가·시가 모두 동방향(둘 다 매수, 또는 둘 다 매도)이라 낭비가 없다 —
포지션이 실제로 전환(−1↔+1)되므로 두 주문이 정당하다.

**진실원천:** [runner.py `run_close_cycle`](../../local/localapp/runner.py) 이 종가창에서
`liquidate_day_trades`(청산) → `enter_close_candidates`(진입)를 **각각 즉시 발주**한다.
둘 사이 상쇄가 없다. 아침 cycle(`_cycle_body` §2 청산 → §3 진입)도 동일 구조.

## 2. 목표 · 비목표

**목표:** 한 발주창에서 같은 종목의 **반대 방향 주문이 겹치는 수량만큼** 브로커 주문을
내지 않고 원장만 이관해, 왕복 수수료를 제거한다. 하락일 종가·시가 양쪽 모두.

**비목표:**
- 백테스트 엔진의 종가매수→익일시가매도 패리티(별건 — 라이브만 대상).
- 상계증거금 자체의 재설계(넷팅은 *주문*을 줄일 뿐, 증거금 계산은 브로커 소관).
- 동방향 주문 병합(수수료는 계약당이라 병합해도 절감 없음 — 하지 않는다).

## 3. 핵심 규칙 — "반대 방향 주문만 상쇄"

한 발주창에서 종목 S에 대한 **청산 주문**과 **진입 주문**의 매매 방향(매수/매도)이
**서로 반대**일 때만 상쇄한다. 상쇄량 `m = min(청산수량, 진입수량)`.

- **반대(매수↔매도):** 하락일 종가(A매도·B매수)·하락일 시가(B매도·A매수) → 넷팅.
- **동방향(매수·매수 또는 매도·매도):** 상승일 → 넷팅 안 함(정상 발주).

수량이 다르면 `m`만 상쇄, 잔여는 정상 발주:
- 청산수량 > m → (청산−m) 정상 청산 발주
- 진입수량 > m → (진입−m) 정상 진입 발주

**불변식 — 상쇄 대상이 없으면 입력을 그대로 반환한다(no-op).** 이것이 현행 동작
byte-identical 보존을 보장한다(특히 골든 테스트가 있는 아침 cycle).

## 4. 장부 이관 (book-transfer) — 전략별 분리 손익

상쇄되는 `m` 계약은 **브로커 주문 없이** 원장에서만 이동한다. 실물 포지션은 불변.
(하락일 종가, A 롱 → B 롱 예시. 시가창은 B→A로 대칭.)

1. **A의 당일 손익 실현**(m계약): `realized_A = (기준가 − A진입가) × m × 승수`.
   전략 A 명의로 `trades.jsonl`에 청산 기록 — **`netted=true`·수수료 0**.
2. A 원장 슬롯 수량 −m (0이면 삭제).
3. **B 원장 슬롯 +m** — 진입가=기준가, entry_date=오늘, side=long, 전략=B, definition=B.
   전략 B 명의로 진입 기록 — **`netted=true`·수수료 0**.
4. 잔여 발주(위 §3).

**기준가:** 넷팅 시점의 현재가(`_safe_price`, 종가/시가 무렵) — 실제 청산이 썼을 참조가와 동일.

**손익 정합성(정직성):** A레그 `(기준가−A진입가)` + B레그 `(익일시가−기준가)`
= `(익일시가−A진입가)` = 실제 총손익. **두 레그 합이 정확히 참값**이므로 분리해도
합계는 정직하다. 기준가는 유일한 분할점이며 `netted` 표시로 "실제 체결 아님·기준가 분할"을
명시한다.

## 5. 통합 구조 — "결정 → 넷팅 → 발주" seam

현행은 결정 즉시 발주한다. 결정(주문 의도 산출)과 발주 사이에 넷팅을 끼운다.

```
local/localapp/netting.py            [신규 · 순수 함수 · 브로커/IO 없음]
    net_window(liquidations, entries) -> NetResult(
        residual_liquidations,   # 정상 발주할 잔여 청산
        residual_entries,        # 정상 발주할 잔여 진입
        transfers,               # book-transfer 목록 (from_sid,to_sid,symbol,qty,ref_price,...)
        savings)                 # [{symbol, qty, commission_saved_krw}]
    · 종목별로 반대방향 주문 min 상쇄, 이관 생성, 절약 수수료 계산
    · 상쇄 대상 없으면 입력을 그대로 잔여로 반환 (no-op = 현행 보존)

trader.py
    · liquidate/enter 경로를 '주문 의도 산출' + '발주'로 분리(청산 클램프·게이트는 산출 단계)
    · _apply_transfer(transfer): 원장 이관 + netted 손익/진입 기록 (브로커 미호출)
    · 잔여 주문은 기존 _submit_* 로 정상 발주

runner.py
    · run_close_cycle: (청산 의도 산출) + (진입 의도 산출) → net_window → 이관 적용 + 잔여 발주
    · 아침 cycle 경로: 동일 seam 적용 (no-op 보장으로 무넷팅 시 현행 보존)

order_log.py
    · 주문/거래 레코드에 netted(bool)·commission_saved 필드
    · cycle 요약에 n_netted·commission_saved_krw

gui.py / gui_format.py
    · 주문내역에 넷팅 행 구분 표시 + 절약액

server/app/routers/trading.py (+ models)
    · cycle 요약의 n_netted·commission_saved_krw 수용·저장 (집계만 — 보안 §4)

web (트레이딩 탭)
    · "오늘 넷팅 N건 · 수수료 X원 절약" + 사이클별 상세
```

## 6. 보존할 불변식 (구현 시 필수 확인)

- **무넷팅 = 현행 byte-identical** (아침 cycle 골든). `net_window` no-op 경로로 보장.
- **청산 먼저 → 진입 나중.** 잔여 발주도 청산 먼저.
- **KIS 실보유 클램프(L-04).** 넷팅은 *클램프된* 청산 수량 기준으로 상쇄.
- **킬스위치·drawdown 게이트.** 게이트로 막힌 진입은 넷팅 대상 아님 → 청산은 정상 발주.
  (넷팅은 게이트 통과한 진입 의도만 대상으로 한다.)
- **유령 진입 불가.** 이관은 기존 원장 포지션만 이동.
- **보안(§4).** 서버엔 집계(건수·절약 KRW)만. 계좌번호·원시주문 미전송.

## 7. 수수료 절약액 산정

절약 = 상쇄된 수량의 **왕복** 수수료 = `m × 계약당수수료 × 2(청산+진입)`.
계약당 수수료는 **엔진 사이징이 쓰는 동일 수수료율**에서 가져온다(별도 하드코딩 금지 —
구현 계획에서 실제 출처를 고정). 슬리피지/스프레드 절약은 추정이 부정확하므로 집계에서 제외하고
문구로만 "실제 절감은 이보다 큼(스프레드 포함)" 정도로 안내.

6. server 집계 수용 + (웹 트레이딩 탭 — 담당 확인 후).
